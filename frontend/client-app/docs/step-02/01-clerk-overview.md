# Крок 2: Інтеграція Clerk — Огляд та підготовка

Цей крок описує повну інтеграцію системи автентифікації **Clerk** у клієнтський React Native додаток, а також підключення до нашого Django-бекенду через Webhook.

---

## Що таке Clerk?

**Clerk** — це сервіс автентифікації, який бере на себе всю складність реалізації входу: зберігання паролів, SMS-коди, OAuth (Google, Apple), сесії та JWT-токени. Ваш Django-бекенд довіряє Clerk і синхронізується з ним через Webhook.

### Архітектура автентифікації в нашому проекті

```
┌─────────────────┐        ┌──────────────────┐        ┌─────────────────┐
│   React Native   │◄──────►│     Clerk API    │◄──────►│  Django Backend  │
│  (client-app)    │        │  (cloud service) │        │   (backend/)     │
└─────────────────┘        └──────────────────┘        └─────────────────┘
        │                          │                             │
        │  1. Реєстрація/Вхід      │                             │
        │─────────────────────────►│                             │
        │                          │  2. Webhook: user.created   │
        │                          │────────────────────────────►│
        │  3. JWT токен            │                             │
        │◄─────────────────────────│  4. Створення User у БД     │
        │                          │                             │
        │  5. API запити з JWT     │                             │
        │────────────────────────────────────────────────────────►
        │                          │                             │
        │  6. Відповідь API        │                             │
        │◄────────────────────────────────────────────────────────
```

### Як це працює в нашому проекті

1. **Користувач реєструється** у додатку (телефон або email).
2. **Clerk** надсилає Webhook `user.created` на наш Django-бекенд.
3. **Django** отримує Webhook та створює запис `User` у базі даних (файл `apps/users/services.py`).
4. При кожному API-запиті **React Native** додає JWT-токен від Clerk у заголовок `Authorization: Bearer <token>`.
5. **Django** перевіряє токен через бібліотеку `clerk-backend-api`, знаходить користувача та обробляє запит.
